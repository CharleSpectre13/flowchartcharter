# Living Playbook & Ascension

Memory is not a static RAG store. It is a **Living Operational Playbook**.

## Ascended Memory Vector
`[Objective Signature, Required KPIs, Capability Map, Evolution Iteration]`

| Field | Role |
|-------|------|
| Objective Signature | 6-dim job fingerprint (domain, complexity, risk, latency, budget, novelty) |
| Abstracted KPIs | *why* it worked (quality, token_eff, latency_ratio, schema, Q_ent) |
| Capability Map | personnel-agnostic skills used |
| Evolution Iteration | generation counter after model upgrades |

## Cross-generational remap
`playbook.upgrade_generation("1T", available_capabilities)`  
Preserves KPIs; rewrites path steps onto new node syntax.

## Automation Ascension
When high-quality records ≥ threshold (default 12):
1. Pattern interpolation (≈80% Job A + 20% Job B)
2. Zero-shot FlowChart synthesis
3. Nodes effectively coach themselves
